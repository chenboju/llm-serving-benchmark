## G0 — 檔案完整性

```bash
bash verify_package.sh
sha256sum "$WORKSPACE_ROOT/models/gpt-oss-20b-gguf/gpt-oss-20b-MXFP4.gguf"
```

`verify_package.sh` 做三件事：比對 `PACKAGE-MANIFEST.sha256`（套件內每個檔案的
SHA-256）、檢查有沒有清單外的檔案、再跑資料集驗證。

| 檢查 | 通過判準 |
|---|---|
| 檔案完整性 | `OK: N 個檔案雜湊全部相符` |
| 多餘檔案 | `OK: 沒有清單外的檔案` |
| 資料集驗證 | `Validated 19 unique file(s) for 79 condition(s).` |
| 模型 SHA-256 | 與參考機完全相同 |
| 模型大小 | 12,109,566,624 bytes |
| HF snapshot | `6cee5e81...` 存在且完整 |

**記錄**：模型 SHA-256、資料集驗證輸出。

資料集已隨資料夾附上並在打包前驗證通過，這一關是確認**傳輸過程沒有損毀**。
雜湊不符就重新複製，不要因為「大小一樣」就往下走。

## G2 — GPU 可見性與遙測

```bash
nvidia-smi --query-gpu=name,compute_cap,driver_version,memory.total --format=csv,noheader
"$LLAMA_SERVER" --list-devices
python scripts/dataset-tests/gpu_telemetry.py
```

| 檢查 | 通過判準 |
|---|---|
| nvidia-smi | 列出 GB10 |
| Compute capability | 記錄實際值 |
| `--list-devices` | 列出 GPU（不是只有 CPU） |
| 遙測後端 | **必須是 `nvidia-smi`** |

**記錄**：GPU 名稱、compute_cap、驅動版本、遙測後端。

GPU 遙測與 idle gate 都會與 4090 那場不一致——修好再跑，不要用 fixed-cooldown 湊合。

## G5 — 雙 backend 單格 smoke

兩個 backend 各跑 `sharegpt-closed-c01`。

| 檢查 | 通過判準 |
|---|---|
| dry-run 命令 | 與參考機一致（含 `--gpu-telemetry pynvml`） |
| llama.cpp 單格 | `status` 為 `valid`、`oom_repeats` 為 0 |
| vLLM 單格 | 同上 |
| 兩邊 tokenizer 路徑 | 完全相同 |

**記錄**：兩邊的 `output_token_throughput` 與 `ttft_p95_ms`。

**參考值**（4090 的 `sharegpt-closed-c01`，llama.cpp）：172.97 tok/s、P95 TTFT 189.95 ms。
GB10 的頻寬較低，數字**預期會低於**這個值——低不是錯誤。但若低到個位數 tok/s，
回頭確認 G2 與 `-DGGML_CUDA=ON` 是否真的生效。

## G6 — Campaign 完整性

```bash
for b in llama-cpp vllm; do
  python -c "import json,sys;d=json.load(open(f'results/$b/dataset/<campaign-id>/campaign-validation.json'));print('$b',d['valid_cells'],'/',d['total_cells'])"
done
```

| 檢查 | 通過判準 |
|---|---|
| 兩邊 cell 數 | 各 45（comparison + prefix）；vLLM stress 另計 34 |
| 有效率 | `valid_cells` = `total_cells`，不等時每個 invalid 都要有根因 |
| Gate 種類 | `repeat-metrics.csv` 的 gate 欄位應全為 `nvidia-smi` |
| 容器存證 | `campaign.json` 的 `vllm_container_command` 有值 |
| Server 存證 | `campaign.json` 的 `llama_server_command` 有值 |

**記錄**：兩個 backend 的 valid/total、invalid cell 清單與根因分類。

**注意**：invalid 不等於失敗。4090 的 HotpotQA 16K C8 與 RULER 60K C2 都是 5/5 invalid，
那是真實邊界。這台記憶體大得多，**同樣的格子若變成 valid，本身就是結論**——
要在報告 7.4 節明確對照。
